# FastBrain 主动回复

让 **FastBrain-9B 判断是否值得主动接话**，再由 AstrBot 当前会话的聊天模型生成实际回复。支持现有 Q4_K_M / llama.cpp SystemOne 服务，也可以使用同协议的 Q8。针对 AstrBot **4.29.3** 开发和测试。

插件默认 `observe`（观察），且群白名单为空：安装后不会自行在任何群发言。请按下方步骤配置接口和群白名单。

## 安装与配置

1. 在 AstrBot 插件管理中上传插件 ZIP，或将此目录放入 `data/plugins/astrbot_plugin_fastbrain_proactive/` 后重载。
2. 填写完整接口地址，例如 llama.cpp 的 `http://127.0.0.1:8080/v1/systemone`，或网关转发的 `http://YOUR_GATEWAY:3067/fastbrain/v1/systemone`；模型别名填 `FastBrain-9B`。这是 SystemOne 接口，不是 `/v1/chat/completions`。
3. API Key 使用有权调用此模型的服务凭证。通过插件配置填写，或将环境变量 `FASTBRAIN_API_KEY` 注入 AstrBot 容器。插件包不带密钥；配置页保存的密钥属于 AstrBot 本地配置，请限制其读取权限。
4. 超管在目标群发送 `/主动回复状态`，将回显的 `平台实例ID:群ID` 填入 `allowed_groups`。这里是平台实例 ID，不是 `aiocqhttp` 这样的适配器类型，也不是完整 UMO。多个群逐项填写。
5. 保持 `mode=observe`，查看状态中的 True 概率、最近耗时和跳过原因；确定策略后改为 `reply`。配置修改后重载插件。`off` 会关闭收集和判断。

主聊天模型、人格、记忆插件、工具权限、原会话历史沿用 AstrBot。插件不替换它们，也不改 UMO。若开启了按群成员隔离会话，判断器使用同一物理群的短期上下文，生成仍落在触发消息原本的会话；只给愿意共享群内上下文的群开启。

**QQ 官方机器人限制：**插件只能看到适配器实际推送给 AstrBot 的消息。如果官方账号只能收到 @ 消息，就没有足够普通群聊可供主动判断；本插件不能让平台推送本来收不到的消息。OneBot、飞书等也以其事件权限为准。插件不拉取历史记录、不增加平台权限。

## 判断策略与阈值

- 群友彼此闲聊、征询使用体验、礼貌收尾，优先不插话。
- @、引用、唤醒消息、明确以 `bot_names` 开头的消息不走主动判断，继续交给原有被动规则。机器人名字只是本插件排除规则，**不会新增 AstrBot 唤醒词**。
- 图片和未转写媒体不理解、不下载；只有媒体没有文字则不判断。混合消息只读文字。
- `decision_persona` 是判定专用精简人格，可以改成睦头当前的人格摘要；**不会自动同步完整会话人格**。实际生成始终使用原会话人格。
- `threshold` 默认 `0.5`，使用 `P(True) >= threshold` 决策。此前数据测试中默认阈值基本全 False；`0.11` 曾作为低阈值实验，但会增加误插话，**不是推荐的通用阈值**。本插件使用更短输入和保守过滤，不能直接套用此前准确率。
- `fewshot` 默认关闭。开启时附加六个短案例（自然承接两例、体验征询/图片/收尾/明确求助四例）。之前实验没有证明 few-shot 稳定提高质量。

FastBrain 返回的概率不是人工核验的准确率；观察模式也调用模型、消耗推理资源。它只保留每群最近一次判断的数值状态，不建立新标注库。

## 如何避免刷屏和积压

事件先经过 AstrBot 的白名单、会话开关、限流、内容检查，然后由插件收集和判断。会话 AI 关闭时不调用 FastBrain。只支持 AstrBot 原生 `local` agent；第三方 agent 或配置了额外模型唤醒前缀时跳过，不绕过这些限制。

默认每群最多每 10 秒判断一次；判 True、收到被动唤醒或机器人应答后冷却 120 秒。一次插件实例只允许一个 FastBrain 请求进行，忙时直接跳过、不排队、不后台补答。判断期间有新消息，旧结果就丢弃；进入主模型前再次检查，排队超过 30 秒也丢弃。已经开始生成的回复不会被后来的群消息强行取消。

实际生成期间保留最长 300 秒的占位；Agent 正常结束时释放，异常退出未触发结束钩子则自动过期，避免永久锁住。超长生成超过占位期仍受 AstrBot 自己的会话锁控制。它不是对整个 AstrBot 所有插件的发送限流器，其他主动发言插件应另行协调。

请求超时默认 15 秒。HTTP 错误、无效概率、错误模型、非法 JSON、超大响应等都保持安静，至少退避 60 秒；服务端 `Retry-After` 更长时遵守它。单次请求不重试、不跟随重定向，日志不记录密钥、原始响应或聊天正文。

## 上下文与缓存

默认每群保留最近 80 条、30 分钟以内的消息，最多缓存 64 个群；全在内存，重载即清空。过期记录在后续访问时惰性清理，有数量上限。真实发送的机器人文本根据 AstrBot 发送标志尽力回填；不代表平台已确认最终送达。

发给 FastBrain 前按最旧消息优先裁剪，完整请求默认不超过 **7168 UTF-8 字节**，给当前 8192 上下文服务的模板和分类结构留余量。这是针对当前 Qwen 系模型的保守字节预算，**不是精确 token 统计**；换服务模板后仍应验证。实际发送的条数通常少于 80；目标消息或人格本身放不下时跳过，不截断目标后猜结论。旧版 4096 上下文的服务请将 `max_request_bytes` 设回 3072。已有插件配置不会自动覆盖，升级后请手动调整这几个值。

发送给主聊天模型的群聊参考放在本轮 `extra_user_content_parts`，标记临时内容；不动态拼接系统提示词、不替换既有历史。它仍会增加本轮输入 token，不能保证服务端缓存命中率。正常对话历史保存遵循 AstrBot 本身机制。

## 超管命令

| 命令 | 用途 |
| --- | --- |
| `/主动回复状态` | 显示群配置值、UMO、模式、阈值、缓冲条数和最近判断 |
| `/主动回复清空` | 清空本群插件缓冲，使尚未生成的旧判断失效；不删除聊天历史/记忆库 |

命令前缀仍以 AstrBot 配置为准。普通成员无权执行以上命令；模式和阈值只从插件配置页修改。

## 测试

测试使用真实 AstrBot 4.29.3 SDK；模型输出和聊天发送用替身，不发真实群消息。覆盖真实唤醒与插件分发、访问控制、观察/回复路径、事件去重、并发过期、冷却、取消、临时上下文和 HTTP 失败处理。

```bash
# 在安装了 AstrBot 4.29.3、pytest、pytest-asyncio 的 Python 3.12 环境中执行。
# conftest 默认将 SDK 数据目录隔离到临时目录；不要指向生产数据。
python -m pytest tests -q
ruff check .
ruff format --check .
```

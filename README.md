# FastBrain 主动回复

让 **FastBrain-9B 判断是否值得主动接话**，再由 AstrBot 当前会话的聊天模型生成实际回复。支持现有 Q4_K_M / llama.cpp SystemOne 服务，也可以使用同协议的 Q8。针对 AstrBot **4.29.3** 开发和测试。

插件默认 `observe`（观察），且群白名单为空：安装后不会自行在任何群发言。请按下方步骤配置接口和群白名单。

## 安装与配置

1. 在 AstrBot 插件管理中上传插件 ZIP，或将此目录放入 `data/plugins/astrbot_plugin_fastbrain_proactive/` 后重载。
2. 填写完整接口地址，例如 llama.cpp 的 `http://127.0.0.1:8080/v1/systemone`，或网关转发的 `http://YOUR_GATEWAY:3067/fastbrain/v1/systemone`；模型别名填 `FastBrain-9B`。这是 SystemOne 接口，不是 `/v1/chat/completions`。
3. API Key 使用有权调用此模型的服务凭证。通过插件配置填写，或将环境变量 `FASTBRAIN_API_KEY` 注入 AstrBot 容器。插件包不带密钥；配置页保存的密钥属于 AstrBot 本地配置，请限制其读取权限。
4. 超管在目标群发送 `/主动回复状态`，将回显的 `平台实例ID:群ID` 填入 `allowed_groups`。这里是平台实例 ID，不是 `aiocqhttp` 这样的适配器类型，也不是完整 UMO。多个群逐项填写。
5. 保持 `mode=observe`，查看状态中的 True 概率、最近耗时和跳过原因；确定策略后改为 `reply`。配置修改后重载插件。`off` 会关闭收集和判断。

主聊天模型、人格、记忆插件、工具权限、原会话历史沿用 AstrBot。插件不替换它们，也不改 UMO。若开启了按群成员隔离会话，判断器使用同一物理群的短期上下文，生成仍落在触发消息原本的会话；只给愿意共享群内上下文的群开启。

**QQ 官方机器人限制：**插件只能看到适配器实际推送给 AstrBot 的消息。如果官方账号只能收到 @ 消息，就没有足够普通群聊可供主动判断；本插件不能让平台推送本来收不到的消息。OneBot、飞书等也以其事件权限为准。插件不拉取历史记录、不增加平台权限。

## 判断策略与阈值

- 未被核心被动回复接管、但明确邀请机器人参与或询问机器人意见的消息可判 True；自然接续互动或存在明确有价值的补充机会也可主动接话，不要求机器人此前说过话。
- 提到 `bot_names` 是参与信号；询问机器人兴趣、经历、能力、偏好、态度，以及期待它表态的调侃更倾向 True。第三人称称呼（如“我们家某某”）也可能是在当面问它。不因单纯备份配置、转述旧话、同名他人或明确请别人回答而强制插话。此倾向写在提示词中，没有按名字加分或降低全局阈值。
- 群友之间的定向交流、一般征询群友使用体验、无意义碎片闲聊与礼貌收尾优先不插话。
- 已被核心唤醒或其他回复流程接管的同一条消息不重复判断；群友 @、引用、@全体也进入 FastBrain，附带匿名化对象及适配器提供的引用文字。仅以 `bot_names` 开头但核心没有接管的普通文字消息会进入 FastBrain；`bot_names` 用来帮助模型识别机器人，**不会新增 AstrBot 核心唤醒词**。
- 不按 `/`、`!`、`！` 等首字符排除消息；实际命令、已唤醒或已处理的消息仍交给 AstrBot 原有流程，避免重复回答。
- 图片和未转写媒体不理解、不下载；只有媒体没有文字则不判断。混合消息只读文字。
- `decision_persona` 是判定专用精简人格，可以改成睦头当前的人格摘要；**不会自动同步完整会话人格**。实际生成始终使用原会话人格。
- `threshold` 默认 `0.5`，使用 `P(True) >= threshold` 决策。此前数据测试中默认阈值基本全 False；`0.11` 曾作为低阈值实验，但会增加误插话，**不是推荐的通用阈值**。本插件使用更短输入和保守过滤，不能直接套用此前准确率。
- 判断提示词开头说明机器人是群聊参与角色，应寻找自然接话机会；一句回应、接住邀请也有价值。
- `fewshot` 为可选开关（新安装默认关闭），开启后附加十八个简短正反例，覆盖未 @ 邀请、功能试用时邀请回应、纠正机器人、报喜、体验征询、仅提到机器人、群友定向交流、礼貌收尾、询问机器人本人和提名互动。v0.1.4 的构造样例对比支持开启，但不代表线上准确率。示例与聊天共享 7168 字节请求预算，会少保留一部分较早消息。

FastBrain 返回的概率不是人工核验的准确率；观察模式也调用模型、消耗推理资源。内存保留每群最近一次状态；运行日志记录消息 ID、概率、判断耗时、排队耗时及最终动作，不记录聊天正文或密钥。线上数据集是单独的可选功能，见下文。

## 线上银标数据集（v0.1.8）

`dataset_enabled=true` 时，所有成功完成的模型 **True 全量保存**，False 按 `false_sample_rate` 抽样（默认 **0.1**）。概率来自 FastBrain，不是人工真值。提名机器人或别称并交办查找、整理、解释、提醒等事项在提示词中明确为 True，引用或 @ 群友不遮盖正文的交办意图；不硬编码关键词强制标签。

保存位置：AstrBot `data/plugin_data/astrbot_plugin_fastbrain_proactive/online-dataset/`。

- `data/online-YYYY-MM-DD.jsonl`：与已有 25,000 条离线银标训练记录相同的 13 个字段，可沿用 JSONL 读取器；`input` 仍是 JSON 字符串，内含相同的 `columns/context/target/pinned_references` 结构和 11 列消息数组。没有把概率、是否发言或判定结论放进训练输入。
- `audit/labels-YYYY-MM-DD.jsonl`：实际送给模型的完整匿名化结构输入、分数、阈值、抽样概率、提示词哈希、延迟及当时的动作（例如 `reply_cooldown`）。FastBrain 不输出解释，`reason=null`，不编造判断理由。
- `audit/outcomes-YYYY-MM-DD.jsonl`：后续生成、发送钩子等事件。发送钩子不等于 QQ 确认送达；缺少结果事件也不能当成确定未发言。
- `ledger.sqlite`：去重账本、策略快照和可恢复导出日志。JSONL 写入失败后，可在后续保存或插件重载时从账本恢复；不要只删除数据库而保留导出文件。

False 使用本机随机种子生成的稳定抽样，长期约 10%，不强凑每十条一条；重启或修改比例不重新抽取已判断的消息。True 受冷却、排队失效或后续流程取消而没发言，仍保留 True，实际动作另存；模型超时/错误、未进入模型的消息不伪装成 False。`/主动回复状态` 显示采集开关和最近写入错误，磁盘错误不阻断聊天；数据库初始化失败需修复磁盘后重载。

格式相同，来源与策略版本保留真实值：`model=FastBrain-9B`、`effort=none`、`label_source=model_silver`、`policy_version=fastbrain-proactive-v0.1.8`。上下文采用本次真实送到 FastBrain 的裁剪结果，收件时间作为相对时间，缺失的引用时间为 null 并在 limitations 中说明。不能把线上提名交办的标签策略和旧版静默策略无区别地混合评价。

文件只写本机、默认关闭采集、不自动上传。结构中的群和消息 ID 使用带本机随机盐的哈希，发言者使用相对编号；**聊天正文仍可能包含个人信息**，不是彻底匿名化数据。训练目录不要提交 GitHub。每日分文件，暂不自动删除历史样本；`/主动回复清空` 仅清空缓冲，不删除数据集。

## 如何避免刷屏和积压

事件先经过 AstrBot 的白名单、会话开关、限流、内容检查，然后由插件收集和判断。会话 AI 关闭时不调用 FastBrain。只支持 AstrBot 原生 `local` agent；第三方 agent 或配置了额外模型唤醒前缀时跳过，不绕过这些限制。

取消每群 10 秒判断间隔；旧 `check_interval_seconds` 设置不再生效。每条合格消息使用收集时的上下文快照，后续普通消息、图片、@、引用都不会使它失效。引用内容最多保留 1024 字符并标记是否裁剪；缺少引用原文时不联网补取、不猜图片内容。

同一实例一次调用一个 FastBrain，请求忙时按序等待，不直接跳过；收集到结果的有效期为 30 秒，超时不补答旧话。接口错误仍按 Retry-After 退避。移除插件、清空缓冲、消息被其他流程接管时取消旧任务。

冷却和正在回复的占位仅限制**实际发言**，不再阻止 FastBrain 判断。多个 True 同时出现时只预约一次回复；其余记录 `reply_pending` 或 `reply_cooldown`，不在冷却结束后补发。观察模式不会创建发言预约或刷新冷却。进入主模型前再次检查任务有效性：被动回复已接管预约、插件关闭、缓冲清空或预约超过 30 秒时取消；新群消息本身不会取消。

实际生成期间保留最长 300 秒的占位；Agent 正常结束时释放，异常退出未触发结束钩子则自动过期，避免永久锁住。超长生成超过占位期仍受 AstrBot 自己的会话锁控制。它不是对整个 AstrBot 所有插件的发送限流器，其他主动发言插件应另行协调。

请求超时默认 15 秒。HTTP 错误、无效概率、错误模型、非法 JSON、超大响应等都保持安静，至少退避 60 秒；服务端 `Retry-After` 更长时遵守它。单次请求不重试、不跟随重定向，日志不记录密钥、原始响应或聊天正文。

## 上下文与缓存

默认每群保留最近 80 条、30 分钟以内的消息，最多缓存 64 个群；全在内存，重载即清空。过期记录在后续访问时惰性清理，有数量上限。真实发送的机器人文本根据 AstrBot 发送标志尽力回填；不代表平台已确认最终送达。

发给 FastBrain 前按最旧消息优先裁剪，完整请求默认不超过 **7168 UTF-8 字节**，给当前 8192 上下文服务的模板和分类结构留余量。这是针对当前 Qwen 系模型的保守字节预算，**不是精确 token 统计**；换服务模板后仍应验证。实际发送的条数通常少于 80；目标消息或人格本身放不下时跳过，不截断目标后猜结论。旧版 4096 上下文的服务请将 `max_request_bytes` 设回 3072。已有插件配置不会自动覆盖，升级后请手动调整这几个值。

发送给主聊天模型的群聊参考放在本轮 `extra_user_content_parts`，标记临时内容；不动态拼接系统提示词、不替换既有历史。它仍会增加本轮输入 token，不能保证服务端缓存命中率。正常对话历史保存遵循 AstrBot 本身机制。

## 超管命令

| 命令 | 用途 |
| --- | --- |
| `/主动回复状态` | 显示群配置值、UMO、模式、阈值、缓冲条数和最近判断 |
| `/主动回复清空` | 清空本群插件缓冲，使尚未生成的旧判断失效；不删除聊天历史/记忆库 |

命令前缀仍以 AstrBot 配置为准。普通成员无权执行以上命令；模式和阈值只从插件配置页修改。

## 测试

测试使用真实 AstrBot 4.29.3 SDK；模型输出和聊天发送用替身，不发真实群消息。覆盖真实唤醒与插件分发、访问控制、观察/回复路径、事件去重、快照排队、引用关系、发言冷却、取消、临时上下文和 HTTP 失败处理。

```bash
# 在安装了 AstrBot 4.29.3、pytest、pytest-asyncio 的 Python 3.12 环境中执行。
# conftest 默认将 SDK 数据目录隔离到临时目录；不要指向生产数据。
python -m pytest tests -q
ruff check .
ruff format --check .
```

本地与 3067 真实接口的协议验证记录见 `TESTING.md`。测试结论不等同于群聊标注准确率。许可证 MIT。
